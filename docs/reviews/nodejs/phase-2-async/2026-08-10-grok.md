## 11.1 Verdict

Phase 2 is the strongest material in the bible so far for depth that still stays operational. One Minor: the production `shutdown.mjs` sketch on page 15 uses undefined `log` / `server` / `db` without a `// pseudo-code` label — brief violation, easy fix. Otherwise the phase is publishable and trustworthy.

## 11.3 Findings

### Minor

```
[MINOR] 15-unhandled-rejections.md:56-78 — shutdown.mjs sketch

Quoted:
// shutdown.mjs — the shape every production service needs
process.on('unhandledRejection', (reason, promise) => {
  log.fatal({ err: reason }, 'unhandled rejection — shutting down');
  …
  server.close(() => {
    db.end().finally(() => clearTimeout(force));
  });
});
```

**What is wrong:** `log`, `server`, and `db` are never defined. The standing brief requires runnable complete examples or an explicit `// pseudo-code` label. This is neither.

**Evidence:** Brief / `instructions.md` §4; file as written is not executable (`ReferenceError` on first rejection).

**Impact:** Copy-paste fails; reader still gets the four design points from the prose.

**Fix:** Prefix with `// pseudo-code — wire log, server, db from your app` or inject minimal stubs so the file runs under `node --check` / a dry smoke.

### Nit

- **01 / 04 race counts:** Page 04 shows 7/3 for main-module race; this machine produced 9/1 over 10 runs. Teaching claim (nondeterministic from main, deterministic in I/O) holds; exact counts are load-dependent.
