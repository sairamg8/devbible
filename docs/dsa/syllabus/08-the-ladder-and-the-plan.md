> Phases 19–20 · The problem ladder mapped pattern by pattern, then the twelve-week plan, the mock cadence and the last two weeks

Knowing the patterns is necessary; solving the canonical problems for each, in order, under
time, is what makes them available in a room. Phase 19 is the ladder: one row per pattern,
naming the problems that define it, so that every phase above has a concrete practice set.
Phase 20 is the plan around the ladder, written for someone with a full-time job and a
System Design track to prepare in parallel.

---

## Phase 19 — The problem ladder, pattern by pattern

Problems are named, not numbered, and grouped the way the well-known ladders group them.
Each row is a pattern with its canonical set; the practice order inside a row is easy, then
medium, then the single hard that proves the pattern.

| Topic | Tier |
|---|---|
| **Arrays and hashing** — two sum, contains duplicate, valid anagram, group anagrams, top-k frequent elements, product of array except self, longest consecutive sequence, encode and decode strings | <span className="db-tier t-master">Master</span> |
| **Two pointers** — valid palindrome, two sum on a sorted array, 3-sum, container with most water, trapping rain water | <span className="db-tier t-master">Master</span> |
| **Sliding window** — best time to buy and sell stock, longest substring without repeating characters, longest repeating character replacement, permutation in string, minimum window substring, sliding window maximum | <span className="db-tier t-master">Master</span> |
| **Stack** — valid parentheses, min stack, evaluate reverse Polish notation, generate parentheses, daily temperatures, car fleet, largest rectangle in histogram | <span className="db-tier t-master">Master</span> |
| **Binary search** — binary search, search a 2D matrix, Koko eating bananas, find the minimum in a rotated sorted array, search in a rotated sorted array, time-based key-value store, median of two sorted arrays | <span className="db-tier t-master">Master</span> |
| **Linked list** — reverse a linked list, merge two sorted lists, reorder list, remove the n-th node from the end, copy a list with random pointer, add two numbers, linked-list cycle, find the duplicate number, LRU cache, merge k sorted lists, reverse nodes in k-group | <span className="db-tier t-master">Master</span> |
| **Trees** — invert, maximum depth, diameter, balanced, same tree, subtree of another tree, lowest common ancestor in a BST, level order, right side view, count good nodes, validate a BST, k-th smallest, build from preorder and inorder, maximum path sum, serialise and deserialise | <span className="db-tier t-master">Master</span> |
| **Heaps** — k-th largest in a stream, last stone weight, k closest points, k-th largest element, task scheduler, design a feed, find the median from a data stream | <span className="db-tier t-master">Master</span> |
| **Backtracking** — subsets, combination sum, permutations, subsets with duplicates, combination sum with duplicates, word search, palindrome partitioning, letter combinations, N-Queens | <span className="db-tier t-master">Master</span> |
| **Graphs** — number of islands, clone graph, max area of an island, Pacific–Atlantic water flow, surrounded regions, rotting oranges, walls and gates, course schedule I and II, redundant connection, number of connected components, graph valid tree, word ladder | <span className="db-tier t-master">Master</span> |
| **One-dimensional DP** — climbing stairs, min-cost climbing stairs, house robber I and II, longest palindromic substring, palindromic substrings, decode ways, coin change, maximum product subarray, word break, longest increasing subsequence, partition equal subset sum | <span className="db-tier t-master">Master</span> |
| **Two-dimensional DP** — unique paths, longest common subsequence, buy and sell with cooldown, coin change II, target sum, interleaving string, longest increasing path in a matrix, distinct subsequences, edit distance, burst balloons, regular-expression matching | <span className="db-tier t-master">Master</span> |
| **Intervals** — insert interval, merge intervals, non-overlapping intervals, meeting rooms I and II, minimum interval to include each query | <span className="db-tier t-master">Master</span> |
| **How the ladders nest** — the 75-problem core inside the 150, the long structured sheets as breadth; the order that works: pattern by pattern, easy then medium then the one hard | <span className="db-tier t-master">Master</span> |
| **The review method** — a mistake log per problem (pattern missed, bug, or time), re-solving after three, seven and twenty-one days, the "explain it in sixty seconds" test | <span className="db-tier t-master">Master</span> |
| **Tries** — implement a trie, design add-and-search words, word search II | <span className="db-tier t-understand">Understand</span> |
| **Advanced graphs** — reconstruct itinerary, min cost to connect all points, network delay time, swim in rising water, alien dictionary, cheapest flights within k stops | <span className="db-tier t-understand">Understand</span> |
| **Greedy** — maximum subarray, jump game I and II, gas station, hand of straights, merge triplets, partition labels, valid parenthesis string | <span className="db-tier t-understand">Understand</span> |
| **Math and geometry** — rotate image, spiral matrix, set matrix zeroes, happy number, plus one, power, multiply strings, detect squares | <span className="db-tier t-understand">Understand</span> |
| **Bit manipulation** — single number, number of 1 bits, counting bits, reverse bits, missing number, sum of two integers, reverse integer | <span className="db-tier t-understand">Understand</span> |
| **Timing drills** — twenty-five minutes for a medium, forty for a hard; reading the solution when time is up, then re-solving the next day without it | <span className="db-tier t-understand">Understand</span> |
| **The whiteboard and the editor** — practising without autocomplete, in the interviewer's tool, camera on, talking | <span className="db-tier t-understand">Understand</span> |

**Gate — move on when:** every Master row has been solved in order at least once, the
mistake log covers every miss, and the second pass of the core set is under the timing
targets for mediums.

## Phase 20 — Interview formats, the plan and the last two weeks

Preparation is a scheduling problem. The rows here are the plan that fits beside a job, the
mock cadence that turns practice into performance, and the taper that keeps the last two
weeks from undoing the first ten.

| Topic | Tier |
|---|---|
| **Interview formats by company type** — product companies tend to run two coding rounds plus design; large firms a phone screen and an onsite loop; startups a take-home or a pairing session. Tendencies only: confirm the actual process for each company before its loop | <span className="db-tier t-master">Master</span> |
| **The twelve-week plan** — weeks one to four patterns at easy and medium, five to eight mediums by pattern plus graphs and DP, nine and ten hards and mocks, eleven and twelve mixed timed sets; one HLD and one LLD per week from the [System Design track](../../system-design/README.md) | <span className="db-tier t-master">Master</span> |
| **Daily structure with a full-time job** — one problem a day minimum, two at weekends, a fixed review slot; what to drop when the week collapses and what never to drop | <span className="db-tier t-master">Master</span> |
| **The last two weeks** — no new topics; timed mixed sets from the ladder, one problem per pattern per day, the mistake log re-read, the "when stuck" protocol rehearsed aloud | <span className="db-tier t-master">Master</span> |
| **The mock cadence** — one peer mock a week from week five, graded against the rubric, recorded and reviewed; acting on one piece of feedback per mock | <span className="db-tier t-understand">Understand</span> |
| **Tracking readiness** — problems per pattern, solve rate, time per medium; the simple dashboard that says whether you are ready rather than whether you feel ready | <span className="db-tier t-understand">Understand</span> |
| **The day-of checklist** — the setup, the tool, the opening questions, the closing summary; when to stop practising the night before | <span className="db-tier t-understand">Understand</span> |
| **After a rejection** — asking for feedback, a cooling-off period, re-entering the ladder at the pattern that failed rather than restarting the plan | <span className="db-tier t-understand">Understand</span> |
| **Contest-style against interview-style** — speed and tricks against communication and clean code; contests for timing practice only | <span className="db-tier t-know">Know</span> |
| **Keeping the edge after the offer** — one problem a week as a maintenance set; DSA as a skill that decays measurably in months | <span className="db-tier t-know">Know</span> |

**Gate — deliverable:** the twelve-week calendar filled in with real dates around your job,
the first two mocks booked, the readiness dashboard started, and the last-two-weeks taper
written down before week one begins.
