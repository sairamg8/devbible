# Webpack — the link map

For every topic on the [Webpack track](../README.md) — written or not — the primary documentation, plus where a good one exists a **Beyond the docs** pick: the best non-official explanation (article, blog, talk, repo) with one line on why it explains the concept differently.
Every link was fetched on the date beside it (2026-10-14). Webpack has no syllabus file, so the topics are our pages: each numbered page is one topic, and a page with several distinct sub-topics gets one block per sub-topic.

| File | Covers | Our page |
|---|---|---|
| [01-webpack.md](01-webpack.md) | All sections · core concepts to multi-config and environments | see each block |

**Reading a block.** **Read this** is the best primary page for the topic. **Also good** adds something the first lacks. **Beyond the docs** is the best non-official explanation found — omitted when none was good enough.
**Covers our angle** says whether it matches what our page promises — *full*, or *partial* and what is missing. **Our delta** is what our own page keeps saying that nobody else does.

**How far to trust a block.** *read* means the passage was read and the claim matches. *Headings only* means the page was fetched and its headings and size checked, but the passage was not read — treat that pick as a strong lead. Each file was written by one agent and then attacked by a second; this is still a first pass and open for review.
