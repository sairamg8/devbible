> Phase 23 · How the rounds fit together, what each level is really asked, and the evidence that gets a senior offer

The rest of this track is what you know. This part is how it is examined, and what beyond
knowledge decides the outcome: the stories you can tell about systems you owned, the work you
can point at, and a preparation plan that survives a full-time job. Nothing here is a
shortcut; it is the part of the loop most engineers leave to chance.

---

## Phase 23 — The senior loop, proof of work and the plan

| Topic | Tier |
|---|---|
| **How product-company loops run** — screening, one or two DSA rounds, machine coding or low-level design, high-level design, hiring manager, a behavioural or bar-raiser round; what each is for, who decides, and where the level is set | <span className="db-tier t-master">Master</span> |
| **Levelling** — SDE-2 vs senior vs staff as scope, ambiguity and influence; the same design question at three levels; the level you interview at versus the one you are offered | <span className="db-tier t-master">Master</span> |
| **The behavioural round** — situation, task, action, result; the six stories to prepare (ownership, conflict, failure, influence without authority, a hard trade-off, a measurable impact); why seniors fail this round more often than the design one | <span className="db-tier t-master">Master</span> |
| **"Tell me about a system you owned"** — context, the decisions, the trade-offs, the numbers, what you would change; the answer that shows ownership against the one that lists technologies | <span className="db-tier t-master">Master</span> |
| **Proof of work** — a deployed project with real traffic and numbers, a merged contribution to a library in this stack, a public design write-up, a talk; what each signals and how to present it in one line | <span className="db-tier t-master">Master</span> |
| **The capstone on the storefront** — Kafka for order events, Kubernetes for the deploy, one LLM feature; deployed, measured, written up; the project you can defend for an hour of follow-ups | <span className="db-tier t-master">Master</span> |
| **The twelve-week plan** — DSA daily, a high-level design twice a week, a low-level design weekly, behavioural stories written and rehearsed; the weekly review and how to adjust when behind | <span className="db-tier t-master">Master</span> |
| **The resume for senior roles** — impact numbers, scope and ownership, one line per system; the mistakes that get a senior resume rejected before anyone reads it | <span className="db-tier t-understand">Understand</span> |
| **Mock interviews** — peer mocks graded against the rubric, recording and reviewing yourself, the cadence that works; what to do with feedback that stings | <span className="db-tier t-understand">Understand</span> |
| **Reading the interviewer** — hints, redirects, the moment they stop asking; recovering a round that is going badly | <span className="db-tier t-understand">Understand</span> |
| **Negotiation basics** — the components of an offer, competing offers, timing, what is negotiable and what is not; the principles, not figures | <span className="db-tier t-understand">Understand</span> |
| **Keeping two backends alive** — Node and Java in parallel: why the second language widens the pool of companies, and how to keep it warm without splitting focus | <span className="db-tier t-understand">Understand</span> |
| **Where the frontend fits** — React depth as the differentiator for fullstack roles: performance, architecture, the frontend rounds that senior fullstack loops include ([frontend architecture](../../frontend-architecture/README.md), [web vitals](../../web-vitals-performance/README.md)) | <span className="db-tier t-understand">Understand</span> |
| **Writing as a senior skill** — design docs, RFCs, postmortems, the public write-up; the review comment that shows judgement | <span className="db-tier t-understand">Understand</span> |
| **Interview logistics** — remote setup, the whiteboard tool you can drive without thinking, thinking aloud on a laggy call, the day-of checklist | <span className="db-tier t-know">Know</span> |
| **After the offer** — notice periods and buyouts, references, the first ninety days as the real interview; keeping the network warm | <span className="db-tier t-know">Know</span> |
| **Handling rejection** — the loop back into the ladder, asking for feedback, cooling-off periods, not re-deriving the whole plan after one bad round | <span className="db-tier t-know">Know</span> |
| **Preparation hygiene** — spaced repetition, the mistake log, sleep, and the burnout pattern that arrives in month two | <span className="db-tier t-know">Know</span> |

**Gate — deliverable:** the six behavioural stories written, the capstone deployed with one
real number on its landing page, the resume cut to one line per system, and the twelve-week
calendar with the first four weeks already done.
