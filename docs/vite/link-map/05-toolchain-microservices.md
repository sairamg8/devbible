# Link map · Vite · Part 5 (sections 17–18)

Covers section 17 (the 2026 toolchain landscape) and section 18 (microservices architecture) of `docs/vite/pages/`. The track has no syllabus, so topics come from our page tree: 3 topic groups in section 17 and 9 in section 18. Groups with several chunks (the dev proxy, Module Federation, and four two-chunk groups) are split into clusters, which gives 3 + 16 = 19 blocks, and every one has a written page of ours.
*read* = I read the passage that supports the claim; *headings only* = fetched at 200, headings or opening checked. Third-party links carry a date only where the page shows one. No `#anchors` are given. Where no good non-official explanation turned up after searching, the block has no "Beyond the docs" line. Two pages (SitePoint, the wala.bearblog post) did not load in the first pass and are not used; webpack.js.org loaded on the second pass and is used.

🔴 **Version note.** Our pages were verified on 2026-09-07 and 2026-09-08 against Vite 8.2.2 and Rolldown. The Vite docs fetched on 2026-10-14 are the v8.3.4 build, so the pinned patch is one minor behind (not a content change). Rolldown reached 1.0 in May 2026 (secondary sources say 2026-05-07 and 2026-05-14; I found no primary post). Vite+ reached 1.0 on 2026-09-28, after our section 17 pages were verified. Official sources here are vite.dev, rolldown.rs, oxc.rs, module-federation.io and webpack.js.org (for the shared-option semantics Module Federation inherits), plus MDN for browser behaviour.

🔴 **Findings in our pages (not edited here).**
- **Vite+ (17/03):** the page has no mention of Vite+ or VoidZero at all (`grep` over `docs/vite/pages` finds none), so it is silent rather than wrong. The silence is the drift: Vite+ 1.0 bundles the very tools the page lists separately (Oxlint, Oxfmt, Vitest 5, tsdown, a task runner), under MIT.
- **Environment API (18/08):** not stale. The page already quotes the "release candidate phase" line and the "some specific APIs are still considered experimental" line, and the v8.3.4 docs still say both. Only the Vite 6 blog (2024-11-26) calls it experimental, which is history.
- **`strictVersion` (18/05a, 05a2, 06):** neither module-federation.io pages nor the Vite plugin README document it. The Module Federation runtime source does implement it: default `false`, and in the version check it calls `error(msg)` instead of `warn(msg)`, but only on the singleton path (github.com/module-federation/core, `runtime-core/src/utils/share.ts`). Our pages describe it as a general "unsatisfiable range is a hard failure", which is stronger than what the code path shows; I did not confirm that `error` throws.
- **Linked packages (18/04b):** the page says a source-consumed workspace package must be added to `optimizeDeps.exclude` or HMR goes stale. The Vite doc says a linked dependency outside `node_modules` is already treated as source and not pre-bundled, so the stale-cache symptom fits only a package resolved through `node_modules`. Needs a recheck.
- **Chunking (17/02):** Vite 8.3 docs name Rolldown's `codeSplitting`; the PkgPulse pick below says `advancedChunks`. Our pages use `codeSplitting`, which matches the docs.
