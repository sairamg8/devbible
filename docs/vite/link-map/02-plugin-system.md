# Link map · Vite · Part 2 (section 08)

Covers section 08 (plugin system) of `docs/vite/pages/08-plugin-system/`. It is one numbered topic page split into 42 chunk files (`01` to `01u`), so it is mapped as ten clusters of chunks, `T08-01a` to `T08-01j`. Each block shows the first chunk file of its cluster and names the chunks it covers. Every block is ✅ written.
*read* = I read the passage that supports the claim; *headings only* = fetched at 200, headings or opening checked. Third-party links carry a date only where the page shows one. Anchors are given only where the heading id was listed from the fetched page. Where a block has no "Beyond the docs" line, two or more searches found only mirrors of the official text, so none is invented.

🔴 **Version note.** Our pages were written against **Vite 8.2.2** (`> Verified: 2026-09-07`, documentation-validated, no sandbox run). Official links point at the current vite.dev and rolldown.rs docs, live on 2026-10-14. The Vite Plugin API page says Vite plugins extend **Rolldown's** plugin interface; older mirrors (v2 to v6 subdomains, mintlify, tessl, jsdelivr copies) describe Rollup and sometimes older names, so they are not used as picks. Third-party picks were written for earlier Vite lines and are flagged where it matters. One page fetched with a newer docs banner (the hotUpdate change note shows docs v8.3.4); the behaviour we cite is unchanged there.

### T08-01c · `config`, `configResolved`, hook kinds and preset coupling — Topic · ✅ written `docs/vite/pages/08-plugin-system/01d-config-and-configresolved.md`
Clusters chunks 01d to 01h: `config` (partial return versus mutation, no plugin adding), `configResolved` and the closure idiom, `sequential` versus `parallel`, accidental serialisation, the preset factory.
- **Read this:** [Plugin API — config and configResolved](https://vite.dev/guide/api-plugin) · vite.dev · `config` (`#config`) is Kind async, sequential, Scope Global, runs before resolution, user plugins are already resolved so adding plugins from it has no effect; `configResolved` (`#configresolved`) is async, parallel, Global, and the docs' `let config` closure is the storing idiom (*read*) · covers our angle: **partial** — has the Kind lines but does not say why a `parallel` violation hides until an `await` appears · fetched 2026-10-14
- **Also good:** [Rolldown Plugin API](https://rolldown.rs/apis/plugin-api) · rolldown.rs · defines async, first, sequential and parallel in prose (sequential: all plugins run in order and async ones are awaited; parallel: async hooks do not block the next one) (*read*) · fetched 2026-10-14
- **Also good:** [Vite 8 migration — Advanced](https://vite.dev/guide/migration) · vite.dev · the sentence "All parallel hooks in Rollup work as sequential hooks", linking to Rolldown; the Rolldown ObjectHook page agrees that hooks always behave as `sequential: true` (*read*) · fetched 2026-10-14
- **Our delta:** the preset factory beats picking the right hook, and why `parallel` is a contract.
