## The one-sentence version

> **`tsc -p` compiles a project; `tsc -b` decides which projects to compile and
> in what order** — and almost everything surprising about it comes from two
> defaults: it skips work when a dependency's declarations did not change, and
> it *keeps going* when a dependency failed.

## Four sentences worth keeping

1. **`references` declares build order and ownership — it does not resolve
   imports.** Module resolution is still workspaces, `node_modules` and
   `exports`.
2. 🔴 **`TS6354` is why references exist.** A dependency rebuilt, its `.d.ts` did
   not change, so the whole downstream graph is skipped — which turns stable
   declarations into a build-time argument for annotating your public surface.
3. 🔴 **`stopBuildOnErrors` defaults to `false`**, so a project whose dependency
   failed is still built. The four diagnostics that imply otherwise only appear
   when you turn it on.
4. **Plenty of monorepos need none of this.** If `tsc` only type-checks, there is
   no intermediate artefact to orchestrate.

## 🔴 The compiler behaviours this topic settles

1. **`stopBuildOnErrors` defaults to `false`**, gating both `getUpToDateStatus`'s
   `UpstreamBlocked` decision and whether `queueReferencingProjects` queues
   downstream work (chunk 03).
2. **`TS6354`** — a project is up to date *with respect to its dependencies'
   `.d.ts` files*, so an unchanged declaration skips the graph below it (chunk
   02).
3. **`TS6381`** — output generated by a different TypeScript version is not
   trusted, which is why an upgrade forces a full rebuild (chunk 02).
4. **`TS6379`** — composite implies incremental and refuses to have it disabled,
   so every composite package writes a `.tsbuildinfo` (chunk 01).
5. **`TS6377`** — the compiler catches two projects colliding on one
   `.tsbuildinfo` path, by name, at build time (chunk 01).
6. **`TS6369`** — `--build` must be first because it selects a different option
   parser, so `tsc --noEmit -b` is rejected rather than reinterpreted (chunk 01).
7. **The `--build` flag set is exactly five** — `--verbose`, `--dry`, `--force`,
   `--clean`, `--stopBuildOnErrors` (chunk 01).
