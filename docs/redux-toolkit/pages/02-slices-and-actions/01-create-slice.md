# 📦 `createSlice`: Reducers, Immer Drafts & `extraReducers`

## 1. Under-The-Hood Mechanics

`createSlice` is a code-generation layer over three classic Redux concepts: action types, action creators, and a reducer function. Given `{ name, initialState, reducers }`, it:

1. Auto-generates an action type string per reducer key: `` `${name}/${reducerKey}` `` (e.g. `'cart/addItem'`).
2. Auto-generates a matching action creator function, exported on `slice.actions`.
3. Wraps every reducer function body in `Immer.produce()`, so mutation-looking code compiles down to structural-sharing immutable updates.

```
dispatch(cartSlice.actions.addItem(payload))
        │
        ▼
Action { type: 'cart/addItem', payload }
        │
        ▼
Immer.produce(currentState, draft => {
  cartReducers.addItem(draft, action)   // your "mutating" code runs against a Proxy draft
})
        │
        ▼
New immutable state tree (only changed branches get new references)
```

### The `prepare` Callback
When a reducer needs to transform its arguments before they become the action payload (e.g. attaching a generated ID or timestamp), pair it with a `prepare` function:

```typescript
addTodo: {
  reducer: (state, action: PayloadAction<{ id: string; text: string }>) => {
    state.push(action.payload);
  },
  prepare: (text: string) => ({ payload: { id: nanoid(), text } }),
},
```

### `extraReducers`: Responding to Foreign Actions
A slice's own `reducers` only handle actions generated by that slice. `extraReducers` lets a slice also respond to actions defined elsewhere — most commonly `createAsyncThunk` lifecycle actions, or another slice's action types.

🔴 **The builder callback is not merely *preferred* — on the pinned version it is the only form that
exists.** RTK 2.0 *removed* the older map-object syntax (`extraReducers: { [thunk.fulfilled]: ... }`)
from both `createSlice.extraReducers` and `createReducer`. A codebase still passing an object there
does not lag behind a convention, it fails to build. The builder is also what makes the whole thing
type-safe, and it is the only form that offers `addMatcher`/`addDefaultCase`:

```typescript
extraReducers: (builder) => {
  builder
    .addCase(fetchCart.pending, (state) => { state.status = 'loading'; })
    .addCase(fetchCart.fulfilled, (state, action) => {
      state.status = 'idle';
      state.items = action.payload;
    })
    .addMatcher(isAnyOf(logout.fulfilled), (state) => { state.items = []; });
},
```

## 2. Real-World Engineering Scenario

**Scenario**: Shopping Cart Slice Shared Across Checkout, Recommendations, and Analytics.
A single `cartSlice` owns cart mutations (`addItem`, `removeItem`, `applyCoupon`), but must also reset itself when an unrelated `authSlice` dispatches `logout`, and must transition into a loading state when a `createAsyncThunk` (`syncCartWithServer`) is in flight. `extraReducers` is the mechanism that lets `cartSlice` react to both without those other modules importing or knowing about `cartSlice` at all — keeping ownership one-directional.

## 3. Production-Grade Code Example

```typescript
import { createSlice, PayloadAction, isAnyOf } from '@reduxjs/toolkit';
import { syncCartWithServer } from './cartThunks';
import { logout } from '../auth/authSlice';

interface CartItem {
  productId: string;
  quantity: number;
  priceCents: number;
}

interface CartState {
  items: CartItem[];
  status: 'idle' | 'syncing' | 'error';
  couponCode: string | null;
}

const initialState: CartState = { items: [], status: 'idle', couponCode: null };

const cartSlice = createSlice({
  name: 'cart',
  initialState,
  reducers: {
    addItem: {
      reducer: (state, action: PayloadAction<CartItem>) => {
        const existing = state.items.find((i) => i.productId === action.payload.productId);
        if (existing) {
          existing.quantity += action.payload.quantity; // Immer traps this mutation safely
        } else {
          state.items.push(action.payload);
        }
      },
      prepare: (productId: string, priceCents: number, quantity = 1) => ({
        payload: { productId, quantity, priceCents },
      }),
    },
    removeItem: (state, action: PayloadAction<string>) => {
      state.items = state.items.filter((i) => i.productId !== action.payload);
    },
    applyCoupon: (state, action: PayloadAction<string>) => {
      state.couponCode = action.payload;
    },
  },
  extraReducers: (builder) => {
    builder
      .addCase(syncCartWithServer.pending, (state) => {
        state.status = 'syncing';
      })
      .addCase(syncCartWithServer.fulfilled, (state, action) => {
        state.status = 'idle';
        state.items = action.payload;
      })
      .addMatcher(isAnyOf(syncCartWithServer.rejected), (state) => {
        state.status = 'error';
      })
      .addMatcher(isAnyOf(logout.fulfilled), () => initialState); // full reset, returning a new object
  },
});

export const { addItem, removeItem, applyCoupon } = cartSlice.actions;
export const cartReducer = cartSlice.reducer;
```

## 4. Senior Engineer Edge Cases & Pitfalls

### ⚠️ Pitfall 1: Mixing Mutation AND Return in the Same Reducer
Immer's contract is strict: either mutate the `draft`, **or** return a brand-new value — never both in the same branch.

```typescript
// ❌ WRONG: mutates draft AND returns a new object — Immer throws at runtime
reducer: (state, action) => {
  state.items.push(action.payload);
  return { ...state, items: [...state.items, action.payload] };
}

// ✅ CORRECT: pick one style per reducer
reducer: (state, action) => { state.items.push(action.payload); }
```

### ⚠️ Pitfall 2: Forgetting `extraReducers` Actions Must Come From Outside the Slice
Reusing a slice's own action inside its own `extraReducers` builder is redundant and a sign the logic belongs in `reducers` instead — `extraReducers` exists specifically for actions this slice does not own (thunk lifecycle actions, other slices' actions).

### ⚠️ Pitfall 3: `prepare` Forgetting to Return `{ payload }`
```typescript
// ❌ WRONG: prepare must return an object shaped { payload, meta?, error? }
prepare: (text: string) => ({ id: nanoid(), text }),

// ✅ CORRECT
prepare: (text: string) => ({ payload: { id: nanoid(), text } }),
```
