## 🔴 Option D was re-priced a SECOND time, and this is the shape to keep

The artifact priced D at *"tier must move out of the page body into frontmatter across
6,519 pages — a scripted migration, and a house-style change the authoring skills have to
learn."* The parent memory already knocked that down to *"a generated `docId → tier` map
read by the swizzled sidebar item"*. **That is still one step more than needed.**

**The tier never has to reach the browser as data at all.** Docusaurus's docs plugin takes
a `sidebarItemsGenerator` hook, which runs on the Node side while the sidebar is being
built and has each doc's `id` **and** its `source` path. So:

```js
sidebarItemsGenerator: async ({defaultSidebarItemsGenerator, ...args}) => {
  const items = await defaultSidebarItemsGenerator(args);
  return decorateSidebarItems(items, buildTierMap({siteDir: dirname, docs: args.docs}));
}
```

and every link item leaves the build with `customProps.tier` on it, every category with
`customProps.tiers = {m,u,k,w,none}` for its whole subtree. What ships to the client is
**one character per sidebar item**, inside the sidebar payload the page already sends.

**Three things this buys, all of which the earlier framings paid for:**

1. **No committed artifact.** A `docId → tier` JSON would be ~6,500 lines that churn
   whenever anyone touches a badge, in a checkout several sessions write to at once —
   a second `progress.js`-shaped conflict hotspot ([[devbible-feedback-shared-file-staging]]).
   Building it in-process costs **~110 ms** at config load, memoised across all 29 sidebars.
2. **No doc-id derivation.** `args.docs` carries `id` and `source` together, so nothing has
   to guess how a file path becomes a doc id — the rule that would rot the day someone sets
   `id:` in frontmatter (4 files already do).
3. **No client-side map lookup**, so no second copy of the corpus in the bundle.

⚠️ It only runs for `{type: 'autogenerated'}` items. Every sidebar in `sidebars.js` is
autogenerated, all 29 — check that is still true before assuming coverage.

## The rule for untiered pages — decided, not deferred

The artifact left it open (*"the 289 pages with no badge need a rule"*). **An untiered page
is always visible, at every floor.** It is a page nobody has tiered yet, and a filter that
swallows it makes it unreachable rather than deferred — the opposite of what a tier floor
is for. Syllabus pages, phase indexes and the whole bucket-A import depend on this.

blanks the sidebar entirely, which is the worse trade.

## 🔴 The theme internals this build rests on (verified in node_modules, 3.10.2)

`@theme-original/DocSidebarItem/Link` and `.../Category` both destructure
`{item, onItemClick, activePath, level, index, ...props}` and **spread `...props` onto the
inner `<Link>` (the anchor)**, while **`item.className` is what lands on the
`<li class="menu__list-item">`**. So a wrapper adds `data-*` attributes and inline styles to
the anchor by passing them as props, and classes to the `<li>` through `item.className` —
and never re-implements the theme component, which owns collapse, auto-expand and the caret.

## What shipped, and the traps each piece found

| Commit | What |
|---|---|
| `5d4d856b` | the tier reader, the vocabulary, the store, the generator hook |
| `5f04a8f3` | `yarn tier-map` — the counting rule's own sum check in one command |
| `7e4db8ea` | visit recording + "next unread at this tier" under the paginator |
| `64858d0e` | report any page whose frontmatter would discard its tier |
| `cbf24572` | the tier floor control and the resume card |
| `29986b13` | the sidebar tree: floor prune, tier dots, size, progress, findings 05/06/07 |

🔴 **The four traps worth not rediscovering** — each cost an agent real time to find:

1. **`className` passed through props REPLACES `menu__link`.** Both `DocSidebarItem/Link`
   and `/Category` build the anchor as `<Link className={clsx('menu__link', …)} {...props}>`
   with **the spread last**, so a className in props wipes Infima's menu styling off the row.
   `data-*` attributes ride the same spread safely. (`item.className` IS clsx-merged, but it
   mints a new item object every render and breaks caches keyed on item identity.)
2. **`hydrate()` must precede `markVisited()`.** `markVisited` derives the new visited set
   from whatever the store holds and writes it back — so calling it before hydration
   persists a one-entry list over the real one, and the `hydrate()` that follows reads the
   truncated list. Nothing throws. Every track silently reads zero.
3. **A category carries `href` but never `docId` in the browser** — `convertCategory`
   discards the link id. So a category can be the reader's *position* but never a "next
   unread" target, and a topic README can never be marked read. That is why the category
   progress bar has **no number**: `11/12` that can never reach `12/12` is a lie.
4. **`href` is optional on a category**, so an unguarded `item.href === permalink` matches
   whenever both are undefined, and the first href-less category in the tree becomes "the
   page you are on".

⚠️ **Never built locally** — [[devbible-feedback-verify-in-ci-not-locally]]. Note
`onBrokenLinks` is now `'throw'`, not the `'warn'` an older memory records.
