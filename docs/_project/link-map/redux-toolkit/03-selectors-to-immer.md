### T11 · `createSelector` and Reselect — Understand · ✅ `docs/redux-toolkit/pages/05-selectors-and-normalization/01-create-selector-and-reselect.md`
- **Read this:** [Deriving Data with Selectors](https://redux.js.org/usage/deriving-data-selectors) · redux.js.org · the maintainers' guide (≈5.5k words): selector basics, why memoize, how `createSelector` behaves and where it stops helping, a "Reselect 5" section (`weakMapMemoize` is now the default — one cache per distinct argument set, no size limit; `memoize: lruMemoize` restores the old behavior), alternative libraries, passing parameters, one selector instance per component · covers our angle: full · fetched 2026-10-05
- **Also good:** [weakMapMemoize → design tradeoffs](https://redux.js.org/reselect/api/weakMapMemoize#design-tradeoffs) · redux.js.org · what the new default costs: strict reference equality on arguments, garbage collection frees only object and function arguments, primitive arguments stay cached until `.clearCache()`, bounded with `maxSize` as of 5.3.0 · fetched 2026-10-05
- **Also good:** [How Does Reselect Work?](https://redux.js.org/reselect/introduction/how-does-reselect-work) · redux.js.org · cascading memoization and how it differs from ordinary memoization, in about 950 words · fetched 2026-10-05
- *Not opened:* no third-party page surfaced — the searches for Reselect and `weakMapMemoize` returned only the official docs, npm, GitHub and package-doc pages.
