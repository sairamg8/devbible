## 03-storage-and-data — Phases 4–5
**Ph 4 · Storage engines, transactions and replication:** B-tree vs LSM (write amplification, read paths, compaction) · WAL and durability · index design and covering indexes (link PG track) · SQL vs document vs wide-column vs KV vs graph vs time-series vs search — choose by access pattern · schema at scale (denormalisation, wide rows) · transactions, isolation levels, MVCC and the anomalies each level permits · replication: sync/async/semi-sync, leader-follower, multi-leader, leaderless quorums (N/R/W) · failover and split brain · read replicas and replication lag (read-your-writes after checkout) · connection pooling at scale (PgBouncer modes, pool per pod) · storage engines in the storefront: orders in PG, sessions in Redis, search in OpenSearch.
**Ph 5 · Partitioning, sharding and the data estate:** vertical vs horizontal partitioning · shard key choice (hash, range, directory), hotspots, celebrity problem · resharding and rebalancing (consistent hashing, virtual shards) · cross-shard queries, joins, transactions, global secondary indexes · Vitess/Citus-style middleware vs application sharding · multi-tenancy models (shared schema, schema-per-tenant, db-per-tenant) · object storage (S3 model, presigned URLs, multipart, lifecycle) · OLTP vs OLAP vs data lake vs warehouse, ClickHouse-style columnar · search engines: inverted index, relevance, sync from the primary (CDC) · time-series and metrics stores · data lifecycle: archival, tiering, GDPR/DPDP deletion · backups, PITR, restore drills · schema migrations at scale (expand/contract, online DDL).

## 04-distributed-systems-theory — Phases 6–7
**Ph 6 · Consistency, clocks and consensus:** the fallacies of distributed computing · CAP as used vs CAP as written; PACELC · consistency models: linearizable, sequential, causal, eventual, read-your-writes, monotonic reads · physical vs logical time: NTP drift, Lamport, vector clocks, hybrid logical clocks, TrueTime · ordering and happens-before · consensus: Paxos idea, Raft in detail (leader election, log replication, membership), ZAB · quorums and majorities · failure detection (heartbeats, phi accrual), leases, fencing tokens · distributed locks and the Redlock debate · idempotency (keys, dedupe tables) and why exactly-once is at-least-once plus idempotency · retries, backoff, jitter, deadlines · gossip protocols · CRDTs and conflict resolution (LWW, merge) · byzantine vs crash faults (Know).
**Ph 7 · Distributed transactions, IDs and the probabilistic toolkit:** 2PC and 3PC, why they stall · sagas: orchestration vs choreography, compensation, the storefront's checkout saga (link Java P14/P15, microservices reference) · TCC · outbox and inbox patterns (link Node phase 7 / real-world phase 2) · distributed ID generation: UUIDv4 vs UUIDv7, Snowflake, ticket servers, ULID/KSUID, index locality · bloom filters, cuckoo filters · HyperLogLog, count-min sketch, top-k · geospatial indexing: geohash, quadtree, S2/H3 · distributed job scheduling and leader-elected cron · workflow engines (Temporal-style durable execution) · distributed rate limiting and counters · leader election in practice (ZooKeeper/etcd locks, Kubernetes leases).

## 05-event-streaming-and-async — Phases 8–9
**Ph 8 · Messaging fundamentals and choosing a broker:** why async: decoupling, buffering, fan-out, time-shifting · queue vs log semantics · push vs pull · delivery guarantees (at-most, at-least, effectively-once) and consumer idempotency · ordering guarantees and their cost · consumer groups and competing consumers · backpressure and bounded queues · dead-letter queues, poison messages, retry topics · message schemas (JSON Schema, Avro, Protobuf), schema registry, compatibility modes · RabbitMQ vs Kafka vs SQS/SNS vs Pub/Sub vs NATS vs Redis Streams — by access pattern (link Java P15, Redis phase 5, microservices reference) · event notification vs event-carried state transfer vs event sourcing · the storefront's order events end to end.
**Ph 9 · Kafka, CDC and event-driven architecture:** brokers, topics, partitions, replication, ISR, KRaft (ZooKeeper removed in the 4.x line — verify on kafka.apache.org before stating) · producers: keys and ordering, acks, idempotent producer, batching/linger/compression · consumers: offsets, commits, rebalancing, lag · transactions and exactly-once within Kafka · retention, compaction, tiered storage · Kafka Connect · CDC with Debezium out of PostgreSQL (logical decoding, outbox via CDC) · stream processing: Kafka Streams / Flink concepts (windows, joins, state, watermarks) · event sourcing + CQRS: when, projections, replays, snapshots · multi-cluster and replication · capacity: partitions per topic, consumer parallelism · Node clients (kafkajs / confluent's client) vs Spring Kafka · operating Kafka: monitoring lag, hot partitions, rebalance storms.

## 06-api-design-and-contracts — Phases 10–11
**Ph 10 · REST done properly:** resource modelling and naming · HTTP semantics (methods, safety, idempotency, status codes) · idempotency keys on unsafe calls · pagination: offset vs keyset vs cursor, stable sort keys · filtering, sorting, sparse fields · error format (problem-details style body, error codes) · versioning strategies (URI, header, evolve-only) and deprecation · conditional requests, ETags, caching headers · rate-limit headers and the 429 contract · bulk and batch endpoints · long-running operations (202 + status resource) · webhooks: signing, retries, idempotent receivers, replay (link Express phase 8 / real-world phase 3) · OpenAPI design-first vs code-first, generated clients and servers, linting/governance · backward compatibility rules · documentation as product.
**Ph 11 · GraphQL, gRPC, tRPC, realtime and contracts:** GraphQL schema design, resolvers, N+1 and DataLoader, persisted queries, federation, depth/complexity limits, caching · gRPC: Protobuf, unary/streaming, deadlines, load balancing, grpc-web, error model · tRPC for TypeScript monorepos (React + Node) · AsyncAPI for events · contract testing (consumer-driven, Pact-style) · BFF and aggregation gateways · realtime APIs: WebSocket, SSE, WebTransport (Know) · REST vs GraphQL vs gRPC decision table · API security at the contract level (link Part 9).
