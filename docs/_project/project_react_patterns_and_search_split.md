## Chunk A — React patterns hub

**Scope: `docs/react/` and nothing else.**

**Deliverable:** a patterns hub inside `docs/react/pages/` that makes the existing
material findable as *patterns*, which today it is not — a reader looking for "compound
components" has to already know it lives under phase 2 topic 8.

1. **Audit first, write second.** Read each page in the table above and record what it
   actually covers. The table is a starting index, not a specification — some rows may
   cover more or less than their title suggests.
2. **Build the hub page.** One entry per pattern: the problem it solves, when it is the
   right answer, when it is not, and a `.md` link to the page that teaches it. The hub
   **teaches selection, not implementation** — implementation stays where it is.
3. **Fill only genuine gaps**, and only after the audit proves they are gaps. Likely
   candidates to *check* (not assumed missing): **headless components**, the **state
   reducer** pattern, **polymorphic components / the `as` prop**, **provider
   composition**, **prop getters**, **container/presenter**. If a candidate turns out to
   be covered, say so and move on — do not write a second page on it.
4. **Never re-implement a pattern the existing pages already implement.** This is the
   same shape as the JavaScript rule for an Understand topic overlapping a Master one:
   write the **concept and the choice**, then link to the implementation.

**Constraints, all inherited and all binding:**
- 🔴 **300 lines is a file-size cap, never a content budget** (global rule 1). If the hub
  runs long, split it into `NN-react-patterns/` with a `README.md` index and chunks.
  Never trim to fit.
- 🔴 **Link the `.md` file, never the directory slug** (global rule 2). Every link ends in
  `.md` and keeps every numeric prefix.
- 🔴 **No sandbox, no console blocks** (global rule 8). Documentation-validated against
  react.dev, with the source named in the `> Verified:` line.
- 🔴 **Per-file cadence** — write a file → update the boards → commit → update this memory.
- **Claim React** in `docs/README.md` and in `docs/react/pages/README.md` first. Nobody
  holds React right now; both parts A and B of the old React split are complete.

**Boards to update:** `src/data/progress.js` (React row only), `docs/react/pages/README.md`,
`docs/README.md`. ⚠️ A prior session recorded that **React reads 100% only because phases
12–13 are missing from `progress.js`** — check that before changing the number.

## Chunk B — local offline search

**Scope: `docusaurus.config.js`, `package.json`, `yarn.lock`. Nothing under `docs/`.**

**Deliverable:** working client-side search across the whole site.

```bash
yarn add @easyops-cn/docusaurus-search-local
```

then a `themes` entry in `docusaurus.config.js`. Points that actually matter here:

- 🔴 **It indexes at BUILD time only.** `yarn start` gives no working search — verification
  is `yarn build` then `yarn serve`. Do not report it broken from the dev server.
- **`hashed: true`** so the index filename changes between builds and clients do not serve
  a stale index from cache.
- **`docsRouteBasePath` / `indexDocs` / `indexBlog`** must match this site's actual routing
  — read `docusaurus.config.js` rather than copying a blog-post config.
- **`language: ["en"]`.**
- ⚠️ **Check compatibility with `@docusaurus/faster`**, which is installed (rspack/SWC
  based). If the plugin and faster mode conflict, **report it — do not silently disable
  faster mode**, since every other session builds against this config.
- ⚠️ **Index size is a real risk.** The corpus is thousands of pages across ~15
  technologies. Measure the generated index size and the build-time delta, and report both.
  If it is unacceptable, say so rather than shipping it quietly.

🔴 **This chunk edits SHARED ROOT CONFIG that every other live session builds against.**
That makes it the higher-risk half despite being the smaller one.
- Get it working in **one commit**, verified, rather than leaving the config half-edited
  across turns.
- **Never `git add -A`** — stage the three paths explicitly.
- 🔴 **Rule 12 applies with full force: claim the row in
  `shared/session_build_devserver_registry.md` and commit the claim BEFORE running
  `yarn build`**, then delete the row the moment it finishes. This chunk cannot be done
  without a build, so the claim is mandatory, not optional.
- Build isolated: `DOCUSAURUS_GENERATED_FILES_DIR_NAME=.docusaurus-search yarn build
  --out-dir build-search`.
