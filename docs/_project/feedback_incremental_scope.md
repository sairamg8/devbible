On [[devbible-brief]], build **only the step that was asked**, then stop and report.

Given "create a dev bible covering 11 technologies", the wrong move — made and
corrected on 2026-08-09 — was scaffolding all 11 sections with folder trees, stub
READMEs and a conventions doc in one pass. The user's response was to delete all of it
and narrow to a single technology's syllabus.

**Why:** The user steers continuously and in small increments, often sending several
refinements while a turn is still running. Large speculative output gets thrown away,
and it buries the one thing they actually asked for. They also want to review a
syllabus before any notes are written against it.

**How to apply:** Syllabus first, approved, then notes — one technology at a time.
When a request could be read as "build everything", build the current focus and list
the rest as clearly-marked placeholders instead. Mid-turn messages are steering:
fold them in rather than finishing the original plan first.
