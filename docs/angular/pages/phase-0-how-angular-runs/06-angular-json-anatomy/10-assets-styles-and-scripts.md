> Verified: 2026-09-09 against **Angular CLI 22.1.7** — the `assetPattern` definition and the
> `assets` / `styles` / `scripts` / `inlineStyleLanguage` properties of
> [`packages/angular/build/src/builders/application/schema.json`](https://github.com/angular/angular-cli/blob/v22.1.7/packages/angular/build/src/builders/application/schema.json)
> at tag `v22.1.7`, and
> [angular.dev/reference/configs/workspace-config](https://angular.dev/reference/configs/workspace-config#assets-configuration),
> quoted verbatim.
> Documentation-validated; **no sandbox run**.
> Version spine: **Angular 22.1.5** (`latest`) · CLI / `@angular/build` / `@angular/ssr` **22.1.7** · TypeScript peer `>=6.0 <6.1`.

**Three options that look like a single "extra files" mechanism and behave nothing alike.**
`assets` copies files without touching them. `styles` adds stylesheets to the build. `scripts` adds
JavaScript that is *not part of the module graph at all*. Two sentences in the documentation account
for almost every question people ask about them, and both are quoted below.

## `assets` — the schema

```json
"assetPattern": {
  "oneOf": [
    {
      "type": "object",
      "properties": {
        "followSymlinks": {
          "type": "boolean",
          "default": false,
          "description": "Allow glob patterns to follow symlink directories. This allows subdirectories of the symlink to be searched."
        },
        "glob":   { "type": "string", "description": "The pattern to match." },
        "input":  { "type": "string", "description": "The input directory path in which to apply 'glob'. Defaults to the project root." },
        "ignore": { "description": "An array of globs to ignore.", "type": "array", "items": { "type": "string" } },
        "output": { "type": "string", "default": "", "description": "Absolute path within the output." }
      },
      "additionalProperties": false,
      "required": ["glob", "input"]
    },
    { "type": "string" }
  ]
}
```

An entry is either a plain string or an object, and **in the object form both `glob` and `input` are
required**. The generated entry omits `output`, which defaults to `""` — the output root:

```json
{ "glob": "**/*", "input": "public" }
```

That default is why `public/favicon.ico` lands at `/favicon.ico` with no configuration.

The docs' field table, verbatim:

> *"| `glob` | A [node-glob](https://github.com/isaacs/node-glob/blob/main/README.md) using `input` as base directory. |"*
> *"| `input` | A path relative to the workspace root. |"*
> *"| `output` | A path relative to `outDir`. Because of the security implications, the Angular CLI never writes files outside of the project output path. |"*
> *"| `ignore` | A list of globs to exclude. |"*
> *"| `followSymlinks` | Allow glob patterns to follow symlink directories. This allows subdirectories of the symlink to be searched. Defaults to `false`. |"*

🔴 **The sentence that answers "why isn't my asset fingerprinted?"** — the `assets` property is
described as: *"Define the assets to be copied to the output directory. These assets are copied
as-is without any further processing or hashing."*

**As-is, without hashing.** `outputHashing: "media"` hashes media *referenced from CSS*; it does
nothing for files copied through `assets`. So a file in `public/` keeps its name forever, and a
browser that cached it keeps the old bytes until something else invalidates them. If you need
cache-busting for such a file, you version the filename yourself or reference it from a stylesheet
so it goes through the media path instead.

⚠️ **`output` cannot escape the output directory** — *"the Angular CLI never writes files outside of
the project output path"*, and the docs say why: security. An `"output": "../somewhere"` does not
error into a useful message; the file simply is not where you expected.

The two worked examples from the documentation:

```json
"assets": [
  { "glob": "**/*", "input": "src/assets/", "output": "/assets/" },
  { "glob": "favicon.ico", "input": "src/", "output": "/" }
]
```

```json
"assets": [
  { "glob": "**/*", "input": "src/assets/", "ignore": ["**/*.svg"], "output": "/assets/" }
]
```

⚠️ **Both use `src/assets/`, which is the pre-v17 layout.** A v22 application generated by `ng new`
has `public/` and no `src/assets/` at all. Copying those examples verbatim into a modern workspace
configures a directory that does not exist.

## `styles` and `scripts`

> *"An array entry for the `styles` and `scripts` options can be a simple path string, or an object
> that points to an extra entry-point file. The associated builder loads that file and its
> dependencies as a separate bundle during the build. With a configuration object, you have the
> option of naming the bundle for the entry point, using a `bundleName` field."*

> *"The bundle is injected by default, but you can set `inject` to `false` to exclude the bundle from
> injection."*

```json
"styles": [
  { "input": "src/external-module/styles.scss", "inject": false, "bundleName": "external-module" }
],
"scripts": [
  { "input": "src/external-module/main.js", "inject": false, "bundleName": "external-module" }
]
```

`inject: false` with a `bundleName` is how you produce a bundle that is *built but not linked into
`index.html`* — something another page, a widget host, or a lazily-inserted tag loads on its own
terms.

Both default to `[]`, and the schema describes them as *"Global styles to be included in the
build."* and *"Global scripts to be included in the build."*

The docs' summary rows are where the important distinction lives:

> *"| `styles` | An array of CSS files to add to the global context of the project. Angular CLI
> supports CSS imports and all major CSS preprocessors. |"*
> *"| `scripts` | An object containing JavaScript files to add to the application. The scripts are
> loaded exactly as if you had added them in a `<script>` tag inside `index.html`. |"*

🔴 **"loaded exactly as if you had added them in a `` `<script>` `` tag"** — that is the whole
meaning of the option, and it is the reason it is misused. A `scripts` entry is **not part of the
module graph**: it is not tree-shaken, not type-checked, cannot be `import`ed, and reaches your code
only through whatever globals it happens to set. It exists for genuinely non-modular JavaScript. A
package with an ESM entry point belongs in an `import`, not here.

## `stylePreprocessorOptions`

> *"In Sass, you can make use of the `includePaths` feature for both component and global styles.
> This allows you to add extra base paths that are checked for imports."*

```json
"stylePreprocessorOptions": {
  "includePaths": ["src/style-paths"]
}
```

```scss
// src/app/app.scss
// A relative path works
@import '../style-paths/variables';

// But now this works as well
@import 'variables';
```

> *"HELPFUL: You also need to add any styles or scripts to the `test` builder if you need them for
> unit tests."*

That note is small and expensive to miss: the `test` target is a different target with its own
options, so a preprocessor path configured for `build` does not exist during `ng test`.

## `inlineStyleLanguage`

The schema: *"The stylesheet language to use for the application's inline component styles."*,
default `"css"`. The docs add the accepted set: *"Accepts `css`, `less`, `sass`, or `scss`, and
defaults to `css`."*

This is why the key is usually absent from a generated `angular.json` — the schematic only writes it
when it differs from the default.

## Gotchas

**★ Symptom: a file in `public/` is served un-hashed, and browsers keep a stale copy after a
deploy.** Cause: assets are *"copied as-is without any further processing or hashing"* —
`outputHashing` does not apply to them. Fix: version the filename yourself, or reference the file
from CSS so it goes through the media pipeline instead:

```css
.logo { background-image: url('./logo.svg'); }
```

**★ Symptom: you copied the documentation's `"input": "src/assets/"` example and nothing is
copied.** Cause: that example predates v17; a v22 application uses `public/`. Fix: use the layout
your project actually has:

```json
{ "assets": [{ "glob": "**/*", "input": "public" }] }
```

**★ Symptom: a global script's symbols are `undefined` when you try to `import` them in a
component.** Cause: `scripts` entries are loaded *"exactly as if you had added them in a `<script>`
tag"* — they are not modules and there is nothing to import. Fix: if the package has an ESM entry
point, import it and drop the `scripts` entry entirely:

```ts
import { thing } from 'some-package';
```

**★ Symptom: `@import 'variables'` works in `ng build` and fails in `ng test`.** Cause:
`stylePreprocessorOptions` is set on the `build` target only, and `test` is a separate target with
its own options. Fix: configure it on both:

```json
{ "targets": { "test": { "options": { "stylePreprocessorOptions": { "includePaths": ["src/style-paths"] } } } } }
```

**★ Symptom: an asset configured with `"output": "../outside-dist"` does not appear there and no
error is printed.** Cause: *"the Angular CLI never writes files outside of the project output
path"*, for security. Fix: write inside the output and move it afterwards if you truly need it
elsewhere:

```json
{ "glob": "**/*", "input": "extra", "output": "/extra/" }
```

**★ Symptom: the build fails validating an `assets` entry that has `glob` but no `input`.** Cause:
the object form requires both, and `additionalProperties` is `false` so a typo in a key name fails
the same way. Fix: supply both, or use the string form:

```json
{ "assets": [{ "glob": "**/*", "input": "public" }] }
```

**★ Symptom: a `styles` entry with `bundleName` never appears in the page.** Cause: you also set
`inject: false`, which builds the bundle without linking it into `index.html`. Fix: that is the
purpose of the pair — drop `inject: false` if you wanted it injected:

```json
{ "styles": [{ "input": "src/theme-dark.scss", "bundleName": "theme-dark" }] }
```

**★ Symptom: assets inside a symlinked directory are not copied.** Cause: `followSymlinks` defaults
to `false`. Fix: opt in explicitly, knowing it changes what the glob traverses:

```json
{ "glob": "**/*", "input": "shared-assets", "followSymlinks": true }
```

**★ Symptom: `inlineStyleLanguage` is missing from your `angular.json` and you conclude inline
styles are unsupported.** Cause: the schematic writes the key only when it differs from the default
`css`. Fix: nothing — set it only if you want another language:

```json
{ "options": { "inlineStyleLanguage": "scss" } }
```

**★ Symptom: excluding one file type from assets by adding a second entry copied it twice.** Cause:
`assets` is a list of independent patterns; a later entry does not subtract from an earlier one. Fix:
use `ignore` within the entry rather than adding another:

```json
{ "glob": "**/*", "input": "public", "ignore": ["**/*.svg"] }
```

## Interview questions

**★ Why is a file in `public/` not fingerprinted, and what do you do about it?**
Because the `assets` option is documented as copying files *"as-is without any further processing or
hashing"* — it is a copy step, not part of the build graph. `outputHashing` covers bundles and, with
`media`, assets referenced from stylesheets; it never touches files copied through `assets`. The
practical consequences are cache-related: a deploy that changes `public/logo.svg` cannot invalidate
a browser's cached copy, because the URL did not change. The options are to version the filename
yourself, or to reference the file from CSS so it goes through the media pipeline and gets a hash.

**★ What is the difference between `scripts` and importing a package?**
`scripts` entries are *"loaded exactly as if you had added them in a `<script>` tag inside
`index.html`"*, so they are outside the module graph entirely: not tree-shaken, not type-checked,
not importable, and reaching your code only through globals. An import participates in the module
graph and gets all of that. The option exists for genuinely non-modular JavaScript — an old library
that assigns to `window` and nothing else. Using it for a package that ships ESM means shipping
everything in that package and losing type checking, which is the common misuse.

**★ What do `bundleName` and `inject: false` do together?**
They produce a separately named bundle that is built but not linked into `index.html`. On its own,
`bundleName` just names the bundle for an extra entry point; adding `inject: false` excludes it from
injection. The combination is how you build a stylesheet or script that something else loads on its
own terms — a theme switched at runtime, a widget hosted on another page, a bundle inserted lazily.
Without `inject: false` it would simply be loaded on every page.

**Why might a Sass import work in `ng build` and fail in `ng test`?**
Because `stylePreprocessorOptions.includePaths` is an option on a target, and `test` is a different
target with its own options — the documentation notes it directly: *"You also need to add any styles
or scripts to the `test` builder if you need them for unit tests."* It is a good illustration of the
general shape of `angular.json`: options are per-target, and nothing is inherited between targets
just because they belong to the same project.

**An `assets` entry with `"output": "../elsewhere"` writes nothing there. Why is that not a bug?**
Because the CLI deliberately refuses to write outside the project output path, and the docs give the
reason as security. An asset configuration is data in a file that many people can edit; letting it
address arbitrary filesystem locations during a build would be a real hazard in CI. The behaviour to
be aware of is that it is a silent constraint rather than a validation error, so the symptom is a
missing file rather than a message.
